## 独立诊断

i082 的优势是完整前缀 trie、最长前缀 checkpoint、请求 cache、常驻 worker、native 合法菜单、谱系回退和独立 root replay。这些基础没有被粗牌组等价类、合成状态或新的判胜条件替代。现有 `StrategicStateEvaluator` 也已经从 metadata、DynamicVars、反射和 IL 读取游戏信息，不是单靠手写牌名强度表。

源码确认了四类宏观问题：相同终局 utility 可在检查不同决策邻域之前被 focus 排除；宽菜单旧 deferred 计数没有对应恢复队列；urgent 优先意味着 focus:explore 不等于全作业算力比例；固定回退距离与不断涌入的晚期来源会让早期修改等待很久。原 frontier 的多样性报告本身不决定 dispatch。它们是机制事实/反例，不是已经测得的胜率损失。

本轮进一步发现，新控制器也可能犯类似错误：新来源按零累计费用进入，就会不断压过已付费的旧来源。因此仅增加一个“公平队列”并不够，接入时间、在途费用、档案淘汰与族并发必须一并检查。完整分析和反例在 I085_TAIL 中。

当前没有匹配的 i082/A10 长尾原始运行面板，无法诚实给出最大的 compute 百分比、主要失败 Act 或 macro/combat 谁更限制胜率。另取回的历史 P5 多种子包属于 A0、180 秒研究设置，已明确排除于当前效力分析。用户提供的 F1→F2 大于 30 分钟现象是研究动机，不被冒充为本轮测得的分布。

## 正确性边界

新增的族、回退尺度、虚拟费用、路线描述符和最佳已观察延续只用于分配；执行始终使用完整实际动作前缀。合法性、原生状态身份、checkpoint、replay 和胜利证书保持原契约。synthetic、缓存重复、超时、beam failure、无解于预算都不是不可行证明。F2 pass 也不是 verified win；后者仍要求独立新进程从初始状态逐动作重放。

所有 native C#/csproj 与被检查的证明/规范化/锁文件相对原基线字节不变。共有的成功后 `verification-timing.json` 是新增观测 IO，不改变判胜，但不声称旧 profile 墙钟时间逐位相同。新关闭参数会出现在配置快照。
