# 正确性契约与证明范围

本页描述独立的有限符号参考内核。其中的完备性和不截取 Top-K 的要求不适用于 holdout-01 的 campaign BeamAdvisor/CombatSolver 搜索。当前发布的证据和限制见 [RELEASE_SCOPE.md](RELEASE_SCOPE.md)。

## 1. 我们实际求解什么

后端提供一个完全可观测、确定性的状态转移系统。`initial()` 给出初始状态，`transitions(S)` 枚举全部合法、参数和嵌套选择均已确定的动作及其唯一后继，`terminal_value(S)` 在终局返回一个整数元组，否则返回 `None`。目标是在可达的、有限步终止的路线中最大化这个整数元组的字典序。

本版是**可执行的符号规则 + 具体状态枚举**。不是 SMT 求解器，也没有自动证明任意程序等价的能力。

证明依赖后端契约：状态是完整的、转移是正确的、合法动作没有遗漏、终局值符合预先声明的目标。JSONL 握手里的布尔声明只是后端承诺，不是其自身的真实性证明。

## 2. 状态的身份

搜索表使用完整的规范化 JSON 字节作为键。Python 字典即便发生内部哈希碰撞，仍会比较字节内容。SHA256 仅用于产物摘要，不能代替完整相等性。

对象字段顺序可规范化，数组顺序不可擅自排序。不同卡牌实例、牌堆顺序、费用修改、RNG 内部状态和消费次数都可能有意义。浮点数不允许进入这个 v1 状态格式；原生 decimal 应以精确系数与小数位或其他无损编码表达，不能四舍五入去重。

真实后端至少需包含：版本/构建/Mod 指纹、角色与飞升、局内隐藏标记、各 RNG 流状态、永久牌组与战斗牌实例、全部有序牌堆、Power/遗物/药水状态、怪物 AI 私有状态和历史、事件队列、挂起选择、跨 Hook 状态，以及终局目标所需的历史累计量。只保留“未来 Markov 状态”却丢失计分所需的历史，同样会得出错误最优解。

没有得到这些字段，不应拿一个看似丰富的 `ContinuationStamp` 或 `StateKey` 直接宣布完整。它们可以是非常好的测试信号，但要逐项审计。

## 3. 唯一的搜索删减

本版仅合并完全相同的状态，不做资源单调性推断，不截取 Top-K，不限制动作深度，也不按启发式分数删除分支。状态图通过 BFS 非递归遍历，避免 Python 递归深度问题。

同一状态第二次到达时，其未来子图已由第一次到达负责展开。闭合循环不是终局，也不是失败证明；它只是不必无限重复展开相同状态。如果每次循环都增加一个隐藏计数、改变 RNG 或增加可兑现资源，那不是同一个状态，必须继续展开。资源预算触顶后返回 `INCOMPLETE`，不能伪装成“检测到无用循环”。

无限增长系统可能没有有限最大值，或者只有上确界。这个版本不自动证明无界性。遇到这种情况，预算中断只是尚未完成。

## 4. 高 HP 并不自动支配低 HP

上一轮设计讨论中“同牌组、同 RNG，HP 和金币更多就能删掉另一个状态”的说法需要收紧。只要存在 HP 阈值、条件触发或资源关联规则，单纯更多就不构成一般性支配证明。

本版用合成的低血阈值反例测试，确保低 HP 分支不会被误剪。真正的支配条件需要证明：对被删状态的每种未来可行行为，保留状态都能实现不差的最终目标。这涉及行为可模拟性，不只是比较几个数值。

## 5. 战斗出口不能过早压成局部最优

`terminal_states` / `exit-states.json` 保留所有不同的终局状态，包括某些局部看来较差的出口。本版没有把不同 RNG、遗物计数、永久成长或牌组差异的出口放进同一个数值 Pareto 表。

要把某一战斗作为整局的宏动作，需让后端终止条件设为真实的战后稳定边界，并把完整跑局后继带给外层规划器。战后掉血、奖励、成长、药水生成和 RNG 消耗都需要有明确归属，不能重复结算或漏掉。

## 6. 什么是本版的闭图证书

`graph.json` 保存根、所有不同状态、全部已枚举动作、后继编号和终局值。只有每个可达非终局节点的生成器正常耗尽，且没有不支持边界与预算截断，才标记 `closed=true`。

`verify_graph()` 不信任搜索器的“已枚举”标记：它重新求出每个状态的终局性和完整后继集合，核对动作、目标、可达性、终局值与声称的最大值。它还拒绝注入不可达的高分状态。完整图检查通过时，能验证该模型的最优终局值。

这份检查器复用同一个模型语义，因此能抓到漏边、证书篡改和搜索层错误，但不能抓到模型与游戏同时不一致的同源规则错误。它不是 Coq/Lean 证明，也不是 STS2 官方规则证明。游戏语义仍需独立的原生逐步差分测试。

`replay.json` 只验证最优候选路线可以在模型里重演。可重演路线是可行性证据，不是“其他路线都不会更好”的证据。两者不可混淆。

## 7. 未完成时必须诚实

状态预算、边预算、展开预算、软时间预算、取消、后端返回 `complete=false`、未知效果，都不允许生成全局最优声明。`upper_bound=null` 的意思是本版没有给出有限有效上界，不是上界等于当前最好值。

时间预算在模型调用之间检查，不能强制打断一个正在执行的本地复杂转移。RPC 另有进程通信超时。预算是工程控制，不是游戏的回合/动作规则；绝不能把人为的搜索上限偷换成完整游戏的边界。

## 8. 新增优化的顺序

先稳定完整模型、全部动作枚举和原生差分，再加高吞吐的 C# 进程内搜索、快照共享、按资源计量的预算与检查点。之后才加入有证据的动作交换、语义等价、支配关系和有效上界。

Beam/RL/LLM 可以作为候选路线或搜索排序来源，不能未经另行证明就为 exact 分支提供删除理由。现有可行候选需要用同一后端重放，不能跨版本照搬分数作为下界。
