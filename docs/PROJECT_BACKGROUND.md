# SpireExact 的项目背景

SpireExact 研究如何为给定的 Slay the Spire 2 种子找到一条完整通关路线。输入包括种子、角色、飞升等级与解锁状态；输出是从新局开始、可以逐步执行和复核的完整动作序列。

研究采用 mode1 全信息设置：搜索可以利用种子所确定的未来。当前对象是 IRONCLAD / Ascension 10 / all unlocks / fresh start，目标是整局胜利，当前每次运行的墙钟安全上限为 30 分钟。

## 为什么把整局放在一起搜索

一场战斗的结果会影响下一次选牌、商店购买、火堆选择和路线分支。前期形成的牌组决定后期能否通过首领；进入最终幕第一首领时的资源，又影响随后第二首领的入场状态。求解器需要把这些决定接成一条贯穿整局的路线。

SpireExact 从地图、选牌、商店、休息与战斗动作中产生候选，执行后读取真实后继状态，再安排下一批偏离和延续。搜索会积累不同的路线谱系、关口入场和失败位置，用这些信息继续分配评估。半小时是目前观察单种子搜索进展的统一预算。

## 从种子到可复核路线

整个流程有四步：

1. **创建新局。** 以确定的种子、角色、飞升与解锁状态建立原生游戏状态。
2. **探索整局决定。** Python 规划器选择地图、奖励、商店、休息和战斗的候选延续，并将完整请求交给宿主。
3. **执行规则。** C# 宿主调用安装版本的游戏程序集，在离线 TestMode 中执行动作，收集后继状态、决策证据与终局结果。
4. **复核获胜路线。** 获胜候选从初始状态在独立新进程中重放，核对动作、决策证据、终局观测和二进制身份，形成胜利证书。

公开仓库中的动作重放入口还会在当前本机构建上执行两次独立新进程重放。重放通过后，工具生成与本机游戏依赖、宿主和源码构建关联的证书。

## 三层协作

| 层次 | 职责 |
| --- | --- |
| Python 整局规划 | 管理候选档案、路线偏离、关口重试、根部策略、评估调度与运行记录 |
| C# 原生宿主 | 创建和恢复游戏状态，执行菜单与战斗动作，导出决策证据和运行身份 |
| CombatSolver 战斗候选 | 在固定源码版本上搜索战斗行动，为整局 rollout 提供候选计划 |

卡牌、遗物、事件和怪物行动的规则执行来自用户提供的游戏程序集。宿主适配原生接口，CombatSolver 的预测与候选计划随后进入原生执行和重放流程。

CombatSolver 固定在 [upstream.lock.json](../upstream.lock.json) 登记的提交。项目自己的 harness 补丁、宿主适配与第三方署名随源码保留，便于查看构建输入与实现来源。

## 支持整局搜索的机制

**检查点与前缀恢复。** 搜索保存稳定地图边界的可恢复状态，让不同候选从同一个已到达位置继续。检查点记录游戏、宿主和初始条件的身份信息；完整动作序列则提供从开局重放的路径。

**常驻隔离 worker。** Python 把原生请求交给独立宿主进程。worker 可以处理多个评估，进程池管理生命周期、超时和内存额度；独立重放使用新进程，从初始状态重新执行。

**根部策略组合。** holdout-01 使用原生策略与 `pick`、`elo` 两种社区统计档位策略，让搜索从多个构筑谱系出发。派生的偏离、重试和延续保留其所属策略，聚焦调度还按牌组相似度限制同一族在精英池中的名额。

**关口模型与多级计划。** 规划器用本次种子的真实首领入场结果更新关口模型，辅助排列候选。首领和精英战使用多束宽搜索计划，最终幕首领采用 `open` 计划；接近过关的失败可以进入关口重试。

**有序派发与证据记录。** 并行 worker 执行请求，协调器按登记顺序吸收结果。每次运行保存设置、源码和二进制指纹、实际资源、候选动作与复核证书，方便把搜索过程与最终结果联系起来。

## holdout-01 留下的结果

`holdout-01` 对 20 个新种子各运行一次。配置为 focus + A+B+open，`solver_seed=271828`，每局 30 分钟安全上限；请求 7 个 worker，实际为 5–7 个。

17 个种子在预算内得到独立重放确认的胜利路线，观察到的解出比例为 **85%**，Wilson 95% 区间为 **64–95%**。获胜候选时刻的中位数为 461 秒，最长为 1,397 秒。其余 3 个种子保留预算结束时的 `UNKNOWN` 结果、资源记录和失败分类。逐次 worker 与机器条件随记录公开，研究设计是每个种子一次固定配置运行。

这些执行记录对应 `frozen-i054a` 与游戏 v0.111.0 的离线 TestMode。仓库公开全部 20 个结果和 17 条完整获胜动作路线，保留每份历史证书的原始身份与摘要。[完整报告](../release/holdout-01/results.md) · [机器可读结果](../release/holdout-01/summary.json)
