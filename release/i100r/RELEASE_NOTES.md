# SpireExact v0.5.0 · i100-r

i100-r 取代 i100 成为公开默认版本：搜索行为回到 i054a（共享内存版 i054a-shm），运行在重构后的核心上。

## 为什么回到 i054a

- i054a 是唯一在真实游戏新种子上做过配对检验的配置。holdout-01：20 个新种子各跑 30 分钟，17 个获胜。iteration-105 A 臂：40 个新种子各跑 2 次、每次 60 分钟，30 分钟内胜 65 / 80 次，60 分钟内胜 70 / 80 次，37 / 40 个种子至少胜一次。
- 同一实验里，i054a 之后加入多项机制的 i101b 用时是 i054a-shm 的 1.23 倍（95% 区间 1.05–1.46，p = 0.005）。
- i100 的关口诊所等机制只在合成战役世界里评估过，没有真实游戏配对证据。

## 重构内容

- **搜索核心**拆成分配器、评估层、吸收和报告；机制移到 `mechanisms.py`，循环本身不含机制。
- **机制登记表**：每个机制有状态和证据，默认配置只能启用 `validated-as-i054a` 和 `infra` 机制；命令行每个参数都必须归类。
- **具名配置** `configs/i054a-shm.toml`，与 iteration-105 A 臂的参数逐项相同。
- **插件挂点**：五个固定挂点；附带 P1 F2 重抽和 P2 置换对照两个实验插件，默认关闭。
- **组件模式**：从录制的关口门前开始，过一个关口就停，用于以分钟级成本比较关口层机制。
- **游戏版本档案**和**求解器登记表**：版本绑定的输入集中到一个文件；一个宿主按请求加载不同的 CombatSolver 构建。
- **分叉保真**：`fork_check` 把 LavaRock 等遗物的显示状态 `RelicModel._status` 归为已解释差异。

## 验收

- 从本仓库源码新编译的宿主，对 iteration-105 的 14 个录制请求重新执行：14 / 14 决策相同。
- 通过前端提交 3 分钟求解：前 116 次评估与 iteration-105 原记录逐条相同（动作、观测、战斗节点数）。
- 命令行 `tools/run_seed.py` 跑 2 分钟：正常结束。
- 四个 .NET 项目构建 0 warning / 0 error；离线测试 72 项通过，1 项需要研究门库而跳过。

记录：`NATIVE_ACCEPTANCE.json`、`ENGINEERING_BUILD.json`、`ENGINEERING_OFFLINE.json`、`ENGINEERING_FRONTEND.json`。

## 使用

- 前端默认预算改为 **60 分钟**（建议值），可选 1–180 分钟。
- 默认求解器 CombatSolver 4d2c550。`cs-0.50.1` 只有登记信息，依赖没有随包提供；20 个关口样本上它没有显示出可以取代默认版本的优势。
- 运行页只提供退出：i054a 的 `escalate` 关口计划不在暂停计时兼容范围内。

## 从 i100 升级

i100-r 与 i100 是两条不同的代码线，不能在 i100 的目录上覆盖升级。请克隆或解压到新目录，重新运行 `tools/setup_source.py` 和 `tools/prepare_local_entry.py`。i100 的源码保留在 `i100-release` 分支。

## 不在本版本内

- 正常 Godot 游戏的逐帧等价、v0.111.0 以外的游戏版本。
- 版本升级流水线、F2 重抽的整局检验，这两项仍在研究中。
